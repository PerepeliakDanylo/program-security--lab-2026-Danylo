## 1. Призначення реєстру

Реєстр — точка входу в карту коду: повний перелік модулів обох компонентів, межі їхньої відповідальності, поточний статус і залежності. Модуль, відсутній у реєстрі, вважається недокументованим; створення модуля без запису тут — порушення політики проєкту.

**Статуси:**

| Статус | Значення |
|---|---|
| `Стабільний` | Реалізовано, перевірено на реальних даних або в грі |
| `У розробці` | Реалізація триває в поточній версії компонента |
| `Специфікація` | Поведінка зафіксована в документації, код пишеться за нею |
| `Заплановано` | Зафіксована потреба; специфікація неповна |

## 3. Модулі компонента `ymt-tweaker`

Фізично компонент — один виконуваний файл `rdr2_reload_tweaker-v5.py` (чинна версія 5.0.1); модулі нижче є логічними зонами відповідальності всередині нього. Розділення на окремі файли можливе надалі й не змінює меж відповідальності.

| Модуль | Відповідальність | Тут НЕ живе | Статус | Залежності |
|---|---|---|---|---|
| `XmlHealing` | Приведення вхідного тексту до придатного для розбору вигляду: зняття BOM, префіксація тегів, що починаються з цифри чи дефіса, екранування «голих» `&`; зворотне відновлення імен при серіалізації | Розбір XML, будь-яке знання про зброю | Стабільний | `re` |
| `TreeTraversal` | Обхід дерева з нормалізацією префіксів `_HEALED_`: пошук прямих нащадків, перших входжень, усіх входжень, вибірка `Item` за атрибутом `type`, читання числових значень | Рішення про те, які саме вузли змінювати | Стабільний | `xml.etree.ElementTree`, `XmlHealing` |
| `ReloadTable` | Таблиця калібрування `RELOAD_CONFIGS`: цільові значення трьох полів і аліаси профілів для 24 стволів | Логіка підбору та запису | Стабільний | — |
| `ConfigResolution` | Детермінований підбір запису таблиці за іменем зброї (точний збіг → найдовший префікс → найдовший підрядок) і побудова зворотного відображення «аліас профілю → запис» | Модифікація дерева | Стабільний | `ReloadTable` |
| `Patching` | Запис трьох полів у знайдені вузли; накопичення оригінальних значень для подальшого експорту | Пошук вузлів, звітність | Стабільний | `TreeTraversal`, `ConfigResolution` |
| `Diagnostics` | Виявлення дублікатів `CWeaponInfo`, записів таблиці без входжень у файлі, профілів без конфігу, ознак повторної обробки файлу | Зміна даних | Стабільний | `Patching` |
| `CsvReport` | Формування `weapons_reload_report.csv` по всіх стволах вхідного файлу | Рішення про зміну значень | Стабільний | `csv`, `Patching` |
| `IniExport` | Формування `DynamicReloadSpeed.generated.ini`: `Calm_*` із таблиці, `Combat_*` зі знайдених значень, закоментовані невідомі | Читання INI, будь-яка взаємодія з плагіном | Стабільний | `ReloadTable`, `Patching` |
| `Cli` | Розбір аргументів (`--report-only`, `--calibrate`, `--rate-model`, `--force-ini`, `--ini`, `--csv`, `--no-ini`, `--no-csv`), пошук вхідного файлу за запасними іменами, вибір шляхів артефактів, коди завершення | Обробка даних | Стабільний | `os`, `sys` |
| `JoaatResolver` | Обчислення joaat-хешів від кандидатів таблиці та зіставлення з іменами профілів, заданими у вигляді `0x`-рядків | Патч значень | Стабільний | `ReloadTable` |
| `Calibration` | Модель часу перезарядки, таблиця замірів `MEASUREMENTS`, виведення трьох значень із однієї цілі `target_full_s`, прогноз за обома моделями темпів, режим `--calibrate` | Робота з XML | Стабільний | `ReloadTable` |
| `AbsentWeapons` | Таблиця `ABSENT_IN_YMT`: стволи, яких у `weapons.ymt` немає в принципі (LeMat, Navy, M1899, Evans, Elephant). Секції для них усе одно потрапляють в експортований INI — їх патчить лише плагін | Будь-яка робота з деревом | Стабільний | `ReloadTable` |

## 4. Модулі компонента `DynamicReloadSpeed.asi`

| Модуль | Відповідальність | Тут НЕ живе | Статус | Залежності |
|---|---|---|---|---|
| `main` | `DllMain`, `DisableThreadLibraryCalls`, реєстрація скрипт-потоку та обробника клавіатури, коректна поведінка при `DLL_PROCESS_DETACH` | Будь-яка логіка мода | Специфікація | ScriptHookRDR2 SDK, `Script` |
| `Script` | Головний цикл, автомат станів `CALM / COMBAT / COOLDOWN`, порядок виклику підсистем, обробка черги запитів від гарячих клавіш, лічильник послідовних помилок | Читання INI, звернення до пам'яті, опитування нативів детекції | Специфікація | `Config`, `CombatDetector`, `WeaponPatcher`, `Overlay`, `Logger` |
| `CombatDetector` | Опитування сигналів бою з власними частотами, правило підтвердження для сигналу прицілювання, сканування ворожих педів у радіусі з обмеженням кількості | Зміна стану, запис значень | Специфікація | `Config`, `Logger`, ScriptHookRDR2 SDK |
| `WeaponPatcher` | Побудова цілей патчингу з адрес, знімок оригіналів, валідація перед кожним записом, запис трьох float-ів, відновлення оригіналів | Вибір профілю, детекція бою, пошук цілей у пам'яті | Специфікація | `MemScan`, `Config`, `Logger` |
| `MemScan` | Пошук цілей за joaat-хешем у закоммічених приватних областях процесу, вимірювання офсета поля за консенсусом стволів, безпечні читання та запис, зміна й відновлення захисту сторінок, `joaat()` як `constexpr` | Знання про зброю, профілі, стани | Специфікація | Windows API, `Logger` |
| `Config` | Розбір INI з терпимістю до помилок, значення за замовчуванням, розв'язання джерел профілів, ланцюжок фолбеків, кламп, зіставлення імені зброї з секцією за найдовшим префіксом, секція `[Memory]` | Доступ до пам'яті гри, рішення про стан | Специфікація | `Logger` |
| `Logger` | Файловий лог із позначками часу, рівнями `off / error / info / debug`, скиданням буфера після кожного запису | Будь-які рішення щодо поведінки мода | Специфікація | — |
| `Overlay` | Екранне відображення поточного стану та версії, вимкнене за замовчуванням | Логіка станів | Специфікація | ScriptHookRDR2 SDK, `Logger` |

## 6. Міжмодульні залежності: правила

- Напрямок залежностей односторонній: `main → Script → {CombatDetector, WeaponPatcher, Overlay}`, `WeaponPatcher → MemScan`. Зворотні залежності заборонені.
- `Logger` — єдиний модуль, доступний з усіх інших; сам не залежить ні від кого.
- `Config` — єдиний власник значень з INI. Інші модулі не читають файл конфігу й отримують уже розв'язані та обмежені значення.
- З нативами гри працюють лише `CombatDetector`, `Overlay` і `main`. `WeaponPatcher` та `MemScan` оперують винятково пам'яттю й Windows API.
- Компонент `ymt-tweaker` не залежить від компонента `DynamicReloadSpeed.asi` і не звертається до нього. Єдиний зв'язок — формат ключів експортованого INI, зафіксований вимогою FR-18; зміна цього формату потребує узгодженої зміни обох компонентів.
