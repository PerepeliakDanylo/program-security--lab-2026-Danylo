## Purpose

`YmtTweaker` (компонент `ymt-tweaker`, чинна версія 5.0.1) володіє:

- Офлайн-перетворенням метафайлу `weapons.ymt`: читанням, лікуванням, розбором, зміною рівно трьох числових полів перезарядки та записом нового файлу.
- Таблицею калібрування `RELOAD_CONFIGS` — єдиним джерелом цільових «повільних» значень для 24 стволів і аліасів їхніх профілів перезарядки.
- Детермінованим правилом зіставлення фактичного імені зброї з записом таблиці.
- Діагностикою вхідного файлу: дублікати `CWeaponInfo`, профілі без конфігу, записи таблиці без входжень, ознаки повторної обробки.
- Формуванням двох артефактів: CSV-звіту по всіх стволах вхідного файлу та INI-конфігу для плагіна.

**NOT here:**

- Рантайм-поведінка, стани `CALM` / `COMBAT` / `COOLDOWN`, детекція бою — `AsiPlugin`.
- Будь-яка робота з пам'яттю процесу гри, резолвінг цілей та офсети полів — `AsiPlugin`.
- Читання INI та застосування значень у грі — `AsiPlugin`; препроцесор лише **записує** INI і ніколи його не читає.
- Видобування `weapons.ymt` з архівів гри та встановлення обробленого файлу назад — сторонні інструменти, поза межами проєкту.
- Баланс зброї (шкода, віддача, розкид, ємність) — не змінюється жодним модулем проєкту.

## Entities

| Entity | Basic Fields | Description | Invariants |
|---|---|---|---|
| `WeaponEntry` | `name`, `occurrenceIndex`, `animReloadRateNode`, `originalAnimReloadRate`, `sectionedRef`, `configKey`, `status` | Один елемент `Item type="CWeaponInfo"` вхідного дерева разом із результатом його обробки. Джерело рядка CSV-звіту. | - Ідентичність — пара `(name, occurrenceIndex)`: імена **не** унікальні, дублікати є нормальним станом злитого файлу.<br>- Елемент без непорожнього `Name` не обробляється й не потрапляє до звіту.<br>- Вузол `AnimReloadRate` ніколи не створюється: його відсутність дає статус `НЕМА AnimReloadRate`, а не додавання вузла.<br>- Змінюється виключно атрибут `value`; структура, порядок і решта атрибутів вузла лишаються незмінними.<br>- `originalAnimReloadRate` фіксується до запису нового значення й лише один раз на кожен `configKey` — повторні входження оригінал не перезаписують.<br>- `sectionedRef` є довідковим полем звіту й не впливає на підбір профілю. |
| `SectionedProfileEntry` *(internal — окремий елемент дерева, не частина `WeaponEntry`)* | `name`, `timeNodes[]`, `loopNodes[]`, `configKey` | Один елемент `Item type="CSectionedReloadInfo"` — профіль поштучного заряджання. На один профіль може посилатися кілька стволів. | - Зіставляється із записом таблиці лише за `SectionedName`, ніколи — за іменем зброї.<br>- Нове значення записується в **усі** вузли `TimeBetweenBulletsInLoop` та `LoopRate` профілю, а не лише в перший.<br>- Оригінальне значення для експорту береться з першого вузла кожного виду.<br>- Профіль без відповідного запису таблиці лишається незмінним і потрапляє до переліку непокритих профілів.<br>- Один аліас належить рівно одному запису таблиці; повторне використання аліаса — дефект конфігурації, що фіксується попередженням. |
| `ReloadProfile` | `key`, `animReloadRate`, `timeBetweenBullets`, `loopRate`, `sectionedAliases[]` | Набір із трьох значень перезарядки для однієї одиниці зброї. Існує у двох іпостасях: **цільовий** профіль із таблиці `RELOAD_CONFIGS` і **зафіксований** профіль — оригінальні значення, знайдені у вхідному файлі. | - `key` — ім'я зброї у верхньому регістрі, унікальне в межах таблиці.<br>- Усі три значення строго додатні; `timeBetweenBullets` вимірюється в секундах, `animReloadRate` і `loopRate` — безрозмірні темпи.<br>- `sectionedAliases` зберігаються у верхньому регістрі; поле-джерело приймає як рядок, так і список рядків.<br>- Зафіксований профіль наповнюється один раз за прохід і після цього не змінюється.<br>- Невідоме значення зафіксованого профілю лишається невідомим: воно не замінюється нулем, середнім чи значенням з таблиці, а експортується закоментованим рядком. |
| `CalibrationTarget` | `weaponKey`, `targetCalmSeconds`, `roundsPerReload`, `mechanism`, `tolerance` | Цільова тривалість повної перезарядки в мирному профілі, з якої виводяться три числа запису таблиці. Пояснює, **чому** значення таблиці саме такі. | - Прив'язаний рівно до одного `ReloadProfile.key`.<br>- `targetCalmSeconds` більший за виміряну ванільну тривалість того самого стволу: мирний профіль за визначенням повільніший.<br>- `tolerance` строго додатний; ціль вважається досягнутою, якщо вимір потрапляє в `targetCalmSeconds ± tolerance`.<br>- `mechanism` визначає, які поля взагалі впливають на результат: для `clip` і `magazine` тривалість задає лише `AnimReloadRate`, а `TimeBetweenBulletsInLoop` / `LoopRate` тримаються нейтральними.<br>- Зміна цілі без нового виміру не дозволяється: ціль і вимір змінюються разом. |
| `Measurement` | `weaponKey`, `profile`, `observedSeconds`, `roundsLoaded`, `gameBuild`, `modsInstalled`, `method`, `date` | Один зафіксований замір тривалості перезарядки в грі. Основа для перевірки, чи досягнуто `CalibrationTarget`, і джерело чисел для нотаток сторінки мода. | - `observedSeconds` строго додатний.<br>- Вимір іммутабельний: уточнення оформлюється новим виміром, старий не редагується й не видаляється.<br>- Вимір без вказаних `gameBuild` і `modsInstalled` недійсний — без них число непорівнянне.<br>- Порівнюватися можуть лише виміри з однаковим `roundsLoaded`: перезарядка з одним набоєм і з повним магазином — різні величини.<br>- `profile` приймає одне з трьох значень: `vanilla`, `calm`, `combat`. |

**Стан реалізації сутностей.** Усі п'ять сутностей реалізовані у версії 5.0.1. `CalibrationTarget` і `Measurement` більше не є лише моделлю: заміри винесені в окрему таблицю `MEASUREMENTS`, ціль задається полем `target_full_s`, а значення таблиці `RELOAD_CONFIGS` виводяться з них обчисленням (FR-63, FR-64). Режим `--calibrate` друкує весь ланцюжок «замір → ціль → три значення» без доступу до файлів.

**Модель часу перезарядки**, з якої виводяться значення:

```
T = A/r  +  N · L/(lr · r)  +  N · tb
```

`r` = `AnimReloadRate`, `lr` = `LoopRate`, `tb` = `TimeBetweenBulletsInLoop`, `N` = кількість набоїв; `A` і `L` — внутрішні тривалості анімацій, що обчислюються зі заміру й не змінюються. Суттєва властивість: **`r` масштабує і поцикловий крок теж**, тому `LoopRate` при зміні темпу не чіпається. Модель підтверджена експериментом у грі 2026-09-21 (FR-66).

Звідси правило перерахунку: щоб зробити перезарядку у `s` разів повільнішою, `r' = r / s`, `lr' = lr`, `tb' = tb · s`.

## Статуси обробки стволу

Значення поля `status` у CSV-звіті; інших значень не існує.

| Статус | Коли встановлюється | Наслідок для вихідного файлу |
|---|---|---|
| `ЗМІНЕНО` | Знайдено запис таблиці і вузол `AnimReloadRate` | Значення перезаписано |
| `БЕЗ ЗМІН` | Запис таблиці не знайдено | Ствол не чіпали |
| `НЕМА AnimReloadRate` | Запис таблиці знайдено, але вузла у стволі немає | Ствол не чіпали, у консоль виведено попередження |

## Ключовий флоу: обробка файлу

- **Вибір входу.** Береться шлях з аргументів; за його відсутності перевіряються запасні імена у фіксованому порядку: `weapons.ymt`, `weapons_merged.ymt`, `weapons (RUCO).txt`, `weapons.txt`. Якщо не знайдено жодного — вивід інструкції та завершення з ненульовим кодом.
- **Читання.** Файл читається як текст у кодуванні `utf-8-sig` з ігноруванням некоректних байтів: вхідні файли походять із різних інструментів і не гарантують чистого UTF-8.
- **Лікування.** Знімається BOM; теги, що починаються з цифри чи дефіса, тимчасово отримують префікс `_HEALED_`; «голі» `&` перетворюються на `&amp;`. Без цього кроку стандартний парсер відмовляє на реальних файлах.
- **Розбір.** Дерево будується стандартним парсером. Помилка розбору після лікування вважається непоправною: причина виводиться, обробка припиняється, вихідний файл не створюється.
- **Збір елементів.** Виокремлюються всі `Item` з `type="CWeaponInfo"` та `type="CSectionedReloadInfo"`; їх кількості виводяться як перша ознака того, що файл прочитано правильно.
- **Обробка стволів.** Для кожного `WeaponEntry`: пошук вузла `AnimReloadRate` (спершу всередині `WeaponReload`, далі — перше входження в межах елемента), читання оригіналу, підбір запису таблиці, фіксація оригіналу для експорту, запис нового значення, формування рядка звіту.
- **Обробка профілів.** Будується відображення «аліас → запис таблиці» з попередженням про дубльовані аліаси. Для кожного `SectionedProfileEntry` зі знайденим записом оригінали фіксуються з перших вузлів, нові значення записуються в усі вузли.
- **Діагностика.** Виводяться: підсумкові лічильники змінених стволів і профілів; дублікати `CWeaponInfo` з позначкою розбіжних значень; записи таблиці, відсутні у файлі; профілі без конфігу (не більше 40 рядків із приміткою про залишок); попередження про повторну обробку, якщо щонайменше половина (але не менше трьох) зафіксованих оригіналів уже дорівнює значенням таблиці.
- **Артефакти.** Записуються CSV-звіт і INI-конфіг, якщо їх не вимкнено аргументами. Помилка запису артефакту не перериває роботу — вона повідомляється й обробка триває.
- **Серіалізація.** У режимі `--report-only` крок пропускається. Інакше дерево серіалізується, знімаються префікси `_HEALED_`, додається XML-декларація, файл записується за вихідним шляхом.

**Boundary.** Флоу закінчується записом файлів на диск. Встановлення обробленого `.ymt` у гру, його запакування в архів і будь-яка перевірка в грі належать користувачеві, а не модулю. Перенесення згенерованого INI у корінь гри виконує людина: прямого зв'язку з плагіном немає.

## Правила підбору конфігу

Застосовуються до імені зброї, переведеного у верхній регістр.

| Крок | Правило | Приклад |
|---|---|---|
| 1 | **Точний збіг** ключа таблиці й імені | `WEAPON_RIFLE_VARMINT` → `WEAPON_RIFLE_VARMINT` |
| 2 | **Найдовший ключ-префікс**: серед ключів, з яких починається ім'я, береться найдовший | `WEAPON_REVOLVER_CATTLEMAN_MEXICAN` → `WEAPON_REVOLVER_CATTLEMAN` |
| 3 | **Найдовший ключ-підрядок**: серед ключів, що входять в ім'я, береться найдовший | `MP_WEAPON_REVOLVER_NAVY` → `WEAPON_REVOLVER_NAVY` |
| 4 | Збігів немає — ствол лишається без змін зі статусом `БЕЗ ЗМІН` | `WEAPON_MELEE_KNIFE` → запис відсутній |

- Порядок кроків фіксований; крок 3 існує лише тому, що у злитих файлах трапляються імена з чужими префіксами.
- Вибір «найдовшого» робить результат незалежним від порядку елементів у таблиці та у файлі: це вимога детермінованості (NFR-14). Варіанти зброї (`*_MEXICAN`, `*_PIG`, `*_EXOTIC`, деградовані та золоті версії) навмисно успадковують налаштування базового стволу.
- Профілі перезарядки цим правилом **не** підбираються: для них діє точний збіг за аліасом `SectionedName`. Причина — імена профілів не мають спільної системи префіксів з іменами зброї, а частковий збіг давав би хибні спрацювання.
- Імена профілів, задані joaat-хешем у вигляді `0x`-рядка (наприклад `0xD06705B5`), зіставляються обчисленням joaat від кандидатів таблиці (FR-11). Хеш, для якого кандидата немає, лишається нерозпізнаним і потрапляє до переліку непокритих профілів — це стан «немає рядка у словнику», а не помилка.
- Таблиця не може містити два записи з однаковим аліасом: така конфігурація робить результат залежним від порядку обходу й фіксується попередженням.

## Правила валідації значень

| Правило | Поведінка |
|---|---|
| Числове значення читається з атрибута `value` вузла | Відсутній атрибут або нечисловий текст дає «значення невідоме», а не нуль |
| «Значення невідоме» у полі оригіналу | Ствол лишається в обробці; у CSV поле порожнє; у INI відповідний ключ `Combat_*` експортується закоментованим |
| Формат запису числа у `.ymt` | Фіксований, з вісьмома знаками після коми — щоб вихідний файл був стабільним і порівнюваним між запусками |
| Формат запису числа в INI | Чотири знаки після коми — достатньо для налаштування й читабельно для людини |
| Значення таблиці `RELOAD_CONFIGS` | Строго додатні; нуль, від'ємне значення та порожнє поле є дефектом таблиці, а не вхідними даними |
| Межі значень | Препроцесор не обмежує значення зверху чи знизу: діапазон `[MinValue, MaxValue]` є правилом рантайму й застосовується плагіном |
| Вхідний файл | Ніколи не змінюється: результат завжди записується в окремий файл |
| Помилка запису артефакту (CSV чи INI) | Повідомляється й не перериває обробку |
| Помилка читання входу або розбору XML | Перериває роботу з ненульовим кодом завершення; вихідний файл не створюється |

## Артефакти та їхні формати

### `weapons_reload_report.csv`

Кодування `utf-8-sig` (файл відкривається в табличних редакторах без ручного вибору кодування). Колонки: `weapon`, `config_key`, `status`, `old_anim`, `new_anim`, `new_loop`, `new_time`, `sectioned_ref`. Сортування: спершу стволи зі статусом `БЕЗ ЗМІН`, далі решта, усередині груп — за іменем. Це робить перелік незачеплених стволів першим, що бачить користувач.

### `DynamicReloadSpeed.generated.ini`

Кодування UTF-8. Починається коментарем із іменем вхідного файлу та поясненням, звідки взято кожну групу значень. Далі — по секції на кожен запис таблиці:

- `Calm_AnimReloadRate`, `Calm_TimeBetweenBulletsInLoop`, `Calm_LoopRate` — з таблиці калібрування;
- `Combat_AnimReloadRate`, `Combat_TimeBetweenBulletsInLoop`, `Combat_LoopRate` — оригінальні значення зі вхідного файлу; невідомі експортуються закоментованими, щоб плагін застосував власні фолбеки;
- секція стволу, відсутнього у вхідному файлі, позначається коментарем-поясненням.

Імена ключів є контрактом із компонентом `AsiPlugin` (FR-18) і не можуть змінюватися в односторонньому порядку. Коректний експорт `Combat_*` можливий лише з **оригінального** `weapons.ymt`: запуск на вже обробленому файлі дасть у бойовому профілі повільні значення, тому цей випадок виявляється окремою діагностикою.
