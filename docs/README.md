## Що описує ця документація

`RDR2 Dynamic Reload` — набір інструментів для одиночної гри Red Dead Redemption 2:

- **`ymt-tweaker`** — офлайн-препроцесор метафайлу `weapons.ymt` (Python 3.8+, тільки стандартна бібліотека);
- **`DynamicReloadSpeed.asi`** — рантайм-плагін (C++17/20, x64, ScriptHookRDR2 SDK), що перемикає темп перезарядки між мирним і бойовим профілями.
- **`tools/drs_release`** — офлайн-інструмент супроводжувача релізів (Python): автентифікація, керування доступом, підпис релізу (ЛР4-ЛР8); у гру не потрапляє.

Репозиторій: https://github.com/PerepeliakDanylo/program-security--lab-2026-Danylo Ліцензія: MIT. Розповсюдження: NexusMods (автор RedziYT) + GitHub.

## Документи, що ведуться разом із кодом плагіна

Ці файли належать компоненту `DynamicReloadSpeed.asi` і створюються в ході його розробки. До комплекту проєктної документації вони не входять, але документи вище на них посилаються.

| Файл | Призначення |
|---|---|
| `docs/DESIGN.md` | Обґрунтування механізму (патч пам'яті vs натив), спосіб визначення офсетів, перелік припущень із зазначенням, чим кожне перевіряється |
| `docs/BUILD.md` | Інструкція зі збірки: що поставити, куди покласти SDK, що робити з помилками компіляції в `GameApi.cpp` |
| `docs/NATIVES.md` | Реєстр кожного використаного натива: ім'я, хеш, точна сигнатура, де підтверджено |
| `docs/UNVERIFIED.md` | Усе, що було потрібне, але не підтверджене в NativeDB чи SDK; порожній файл — валідний результат |
| `docs/TESTPLAN.md` | Приймальний чек-лист; кожен пункт перевіряється за рядками лог-файла |
| `docs/MOD_PAGE_NOTES.md` | Фактичні твердження для сторінки мода на NexusMods: виміряні числа, підтверджена сумісність, обмеження |

## Порядок внесення змін

1. Зміна поведінки спершу фіксується у специфікації (`specification/requirements.md`), і лише потім у коді — проєкт ведеться за Specification-Driven Development.
2. Зміна модуля супроводжується звіркою відповідного `business_logic.md` і записом у `changelog.md`.
3. Зміна політики — окремою задачею, окремим комітом із префіксом `[POLICY]` та інкрементом версії документа.

## Конвенції документації

- Мова документації — українська; технічні ідентифікатори (`AnimReloadRate`, `CWeaponInfo`, `FR-01`) — латиницею в оригінальному написанні.
- Кожен великий документ починається таблицею-шапкою: назва, версія, статус, дата оновлення, власник, пов'язані документи.
- Діаграми — у блоках Mermaid, щоб рендеритися безпосередньо на GitHub.
- Ідентифікатори наскрізні: `FR-xx` / `NFR-xx` — вимоги, `AD-xx` — архітектурні рішення, `E/P/D/F/TB` — елементи діаграми потоків даних.
