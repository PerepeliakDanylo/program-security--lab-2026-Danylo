## Для чого цей документ

Тут лежить те, що **хотілося** мати, але що не підтверджене. Правило SR-19: непідтверджене
фіксується тут і **не викликається**. Документ існує, щоб «ми цього не знаємо» було записаним
фактом, а не забутим у процесі.

**Порожній `UNVERIFIED.md` — допустимий кінцевий стан.** Коли всі записи закриті, тут лишається
шапка й рядок «відкритих питань немає, станом на <дата>».

**Порожній через те, що записи повидаляли, — недопустимий стан.** Запис закривається лише
відповіддю: підтвердженням із `natives.h` і `rdr3 nativedb`, рядком лога з прогону або свідомою
відмовою від механізму. Закритий запис не видаляється: він лишається тут із датою, відповіддю й
посиланням на артефакт, де відповідь видно.

Формат кожного запису однаковий: **для чого хотілося → що використано натомість → яке саме питання
треба закрити → чим закривається**. Ідентифікатори іммутабельні; `A-x` збігаються з номерами
припущень у `DESIGN.md`.

## 1. Сигнали й API

### U-01. Сигнал «розшук законом» — **ЗАКРИТО 2026-09-28**

| | |
|---|---|
| **Для чого хотілося** | Перестрілка з законом — найчастіший бій у грі. Ознака «гравця розшукують» мала б переводити стан у `COMBAT` навіть тоді, коли гравець тікає, не стріляє й ще не отримав шкоди |

### U-05. Маркер класу, за яким 1.2 розпізнає `CWeaponInfo` (1.2) — **ЗАКРИТО 2026-10-27**

> **Відповідь (прогін 1.2.0, обидва запуски):** маркер знайдено — `qword at name-0x20 =
> RDR2.exe+0x33D9948 on 59 names`, у кожного з 59 імен 1-4 об'єкти, включно з LeMat, Navy, M1899,
> Evans, Elephant, High Roller і Navy crossover (`7 class only` — саме ці сім, без еталонного
> значення). Гіпотезу підтвердило поле перезарядки: `calm ok=1 sig=52` на сповільненому файлі,
> `stock ok=1 sig=52` на стоковому. Прив'язки однакові в обох запусках (AT-75). Таблиця нижче —
> як була записана до прогону.

| | |
|---|---|
| **Для чого хотілося** | Прив'язати кожну зброю саме до її `CWeaponInfo`, а не до першої структури, що згадує ім'я (дефект 1.1.0, `DESIGN.md` §3.7) |
| **Що використано** | Маркер **вивчається з даних**: вирівняне 8-байтове значення в межах `[-0x100, +0x10]` від імені, що вказує в образ `RDR2.exe` і спільне для десятків імен з 1-4 об'єктами кожне; кожна гіпотеза перевіряється пошуком поля перезарядки серед її об'єктів |
| **Питання** | (1) Чи знаходиться такий маркер на 1.0.1491.50 (очікувано — vtable `CWeaponInfo` на зсуві, що відповідає початку об'єкта)? (2) Чи справді його мають усі `CWeaponInfo`, включно з DLC-зброєю (LeMat, Navy, M1899, Evans, Elephant, High Roller)? |
| **Чим закривається** | `TESTPLAN.md` AT-72 (рядок `weapon-info class recognised …`), AT-73 (усі імена прив'язані), AT-74/AT-75 (DLC-зброя стабільна між запусками) |
| **Наслідок, якщо хибне** | Резолвер переходить на пошук без класу й прив'язку **лише за точним значенням** (`value only`); зброя без відомого значення й зброя поза таблицею цієї сесії не перемикаються. Безпечна деградація, не хибний запис |

### U-06. Формат мітки зброї `_GET_WEAPON_NAME` (1.2) — відкрите (уточнено 2026-10-27)

> **Що показав прогін 1.2.0:** справжньої зброї поза таблицею в грі розробника немає, тож форму
> «`WNS_…`» побачити не вдалося. Для двох псевдостволів мітка — **саме внутрішнє ім'я**
> (`label WEAPON_RAMMED_BY_CAR`); 1.2.0 таку мітку не звіряла з хешем (`name not verified`),
> 1.2.1 звіряє. Питання про `WNS_` лишається відкритим до першої зброї поза таблицею (DLC чи мод).

| | |
|---|---|
| **Для чого хотілося** | Назвати зброю поза таблицею й підібрати їй секцію INI за префіксом |
| **Що використано** | `WEAPON::_GET_WEAPON_NAME` (`0x89CF5FF3D363311E`, `const char* (Hash)`); «`WNS_X`» → «`WEAPON_X`», перевірка `joaat(ім'я) == хеш`. Рядок копіюється одразу під SEH (`MemScan::readCString`) |
| **Питання** | Чи мітки справді мають вигляд «`WNS_<внутрішнє ім'я без WEAPON_>`» (у базі — лише «`WNS_INVALID` для невідомого хеша»)? |
| **Чим закривається** | AT-77: рядки `unlisted gun: … (label …, name verified\|not verified)` |
| **Наслідок, якщо хибне** | Зброя отримує ім'я-мітку або `0x<хеш>`, секції INI за префіксом не знаходить і йде на `[Defaults]` (лише якщо завантажене значення стокове 1.00/1.30, інакше лишається як є) |

### U-07. Внутрішнє ім'я High Roller і «Револьвера гравця» (1.2) — **ЗАКРИТО 2026-10-27**

> **Відповідь:** `WEAPON_REVOLVER_DOUBLEACTION_GAMBLER` є в пам'яті (`59 of 59`) і в руках дає
> `weapon in hand: WEAPON_REVOLVER_DOUBLEACTION_GAMBLER - managed (1 structure(s)), reload rate now
> 0.3800` (запуски 1 і 2). `WEAPON_REVOLVER_NAVY_CROSSOVER` теж є в пам'яті й має рядок `plan:`.

| | |
|---|---|
| **Для чого хотілося** | «Револьвер гравця» (так у локалізації Дана) у тесті 1.1.0 перезаряджався з ванільною швидкістю в обох режимах (3.38 с) — його не було в таблиці |
| **Що використано** | У таблицю додано `WEAPON_REVOLVER_DOUBLEACTION_GAMBLER` (High Roller; у сюжеті з PC-версії 2019, у скупника) і `WEAPON_REVOLVER_NAVY_CROSSOVER`. Імена не підтверджені жодним джерелом із хешами; хибне ім'я дає лише `hash not found in memory`, а зброю все одно підхоплює прохід класу |
| **Чим закривається** | AT-76: рядок `weapon in hand: <ім'я> …`, коли «Револьвер гравця» в руках |

### U-08. `GET_PED_SOURCE_OF_DEATH` у кадрі пострілу (1.2) — відкрите (у прогоні не перевірялось окремо)

| | |
|---|---|
| **Для чого хотілося** | Постріл, що вбив людину одразу, — теж «постріл у людину» (`AttackingHumans`) |
| **Що використано** | Ціль під прицілом мертва → рахується, якщо `PED::GET_PED_SOURCE_OF_DEATH(ціль) == гравець` (`0x93C8B64DEB84728C`, `Entity (Ped)`) |
| **Питання** | Чи виставляє гра джерело смерті до того, як скрипт бачить `IS_PED_SHOOTING` у тому самому кадрі? |
| **Чим закривається** | AT-78, варіант: убити NPC одним пострілом у голову → `CALM -> COMBAT (attacking…)` |
| **Наслідок, якщо хибне** | Лише вбивство з першого пострілу не вмикає бій (живу ціль сигнал ловить); зазвичай далі спрацьовують «ворог поруч» або «розшук» |

### U-09. `IS_WEAPON_A_GUN` для луків і метальної зброї (1.2) — **ЗАКРИТО 2026-10-27: одного прапорця замало**

| | |
|---|---|
| **Для чого хотілося** | Перемикати лише вогнепальну зброю поза таблицею |
| **Що використано** | `WEAPON::IS_WEAPON_A_GUN` («прапорець `Gun` у `CWeaponInfoFlags`»); додатково виключаються за хешем `weapon_bow*`, `weapon_turret_*` і за міткою (`TURRET`, `CANNON`, `GATLING`, `MAXIM`) |
| **Чим закривається** | AT-77: серед `unlisted gun:` немає луків, метальної зброї, турелей |
| **Відповідь (прогін 1.2.0)** | Луків, метальної зброї й турелей серед прийнятих немає, але прапорець `Gun` стоїть і на псевдозброї шкоди від транспорту: прийнято `WEAPON_RAMMED_BY_CAR` і `WEAPON_RUN_OVER_BY_CAR`. 1.2.1 вимагає ще й клас вогнепальної зброї — U-11 |

### U-10. Друга рука: точка кріплення 1 і об'єкт зброї в ній (1.2.1) — **ЗАКРИТО 2026-10-28** (AT-86 – AT-88)

| | |
|---|---|
| **Для чого хотілося** | Показати на оверлеї другий револьвер при стрільбі з двох рук: `x2` для однакових, третій рядок для різних (побажання розробника з тесту 1.2.0) |
| **Що використано** | `WEAPON::GET_CURRENT_PED_WEAPON(ped, hash, TRUE, 1, FALSE)` — точка кріплення 1 = `WEAPON_ATTACH_POINT_HAND_SECONDARY` за переліком `eWeaponAttachPoint` у коментарі бази до `SET_CURRENT_PED_WEAPON`; плюс `WEAPON::GET_CURRENT_PED_WEAPON_ENTITY_INDEX(ped, 1)` ≠ 0 — у цій руці справді є об'єкт зброї; плюс обидва стволи — револьвер/пістолет (U-11) |
| **Питання** | (1) Чи друга рука в цій грі — саме ліва рука при стрільбі з двох рук? (2) Чи віддає гра для порожньої другої руки 0/`WEAPON_UNARMED` або хоча б нульовий об'єкт, щоб не з'являлось хибне `x2` з одним револьвером? |
| **Чим закривається** | `TESTPLAN.md` AT-86 (`x2`), AT-87 (третій рядок), AT-88 (жодного `x2` з одним стволом і жодного рядка для опущеної рушниці) |
| **Наслідок, якщо хибне** | Лише вигляд оверлея: другої руки не видно (як у 1.2.0) або видно зайве. Перемикання темпів від цього не залежить — воно глобальне для кожного `CWeaponInfo` |

## 2. Припущення з `DESIGN.md`

### A-1. Ім'я зброї зберігається як joaat-хеш — **ЗАКРИТО 2026-10-19**

| | |
|---|---|
| **Відповідь** | Стратегія A працює: `24 of 24 weapon names present in memory` (1.0.0), `57 of 57` (1.1.0). Стратегія B (ASCII + вказівник) написана в `MemScan`, але до резолвера не підключена й не потрібна |

### A-2. Цілі лежать поза образом модуля `RDR2.exe` — **ЗАКРИТО 2026-10-19**

| | |
|---|---|
| **Відповідь** | Усі знімки — `in-module: no`: структури в купі, як і передбачалося. Додаткова перевірка меж модуля не застосовна |

### A-3. Порядок полів збігається з XML, чотири блоки станів лежать підряд — **ЗАКРИТО ЧАСТКОВО 2026-10-22**

| | |
|---|---|
| **Відповідь** | Порядок полів підтверджено: `LoopRate` на `0x30`, `TimeBetweenBulletsInLoop` на `0x54` від імені профілю (3-й і 10-й `float` блока з `0x28`), стокові значення в 19/19 і 18/19 профілях (лог 1.1.0). Крок між блоками в грі не перевірявся |
| **Чому далі не блокує** | З 1.2 секційні поля типово не пишуться (`PatchSectionedReload = 0`, `DESIGN.md` §1): у грі розробника вони стокові, і на цьому стані відкалібровано всі `Calm_*`. Крок потрібен лише з `= 1` |

### A-4. П'ять відсутніх стволів існують у пам'яті як `CWeaponInfo` — **ЗАКРИТО 2026-10-20**

| | |
|---|---|
| **Відповідь** | Хеші всіх п'яти в пам'яті є, і в обох логах 1.1.0 для них знайдено структури з правдоподібними значеннями (Evans 1.30, решта 1.00) — `CWeaponInfo` для них створюється з іншого метафайлу. Твердження сторінки мода правдиве для всіх п'яти |
| **Що виявилося окремою проблемою** | 1.1.0 прив'язувала їх «за правдоподібністю» — щоразу до іншої структури (Navy 1.0 → 3.0094, LeMat 0.1042 → 1.0). Це закриває U-05 |
