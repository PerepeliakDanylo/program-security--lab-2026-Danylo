Терміни згруповані за областю. Написання ідентифікаторів збережено в оригіналі; український відповідник наводиться там, де він усталений.

## 1. Гра та платформа модифікацій

| Термін | Визначення |
|---|---|
| RDR2 | Red Dead Redemption 2, гра Rockstar Games. Проєкт стосується виключно її одиночного режиму (`Story Mode`) |
| RAGE | Rockstar Advanced Game Engine — ігровий движок RDR2. Визначає формати даних (`.ymt`, `.rpf`), спосіб хешування рядків (joaat) і розкладку C++-структур, з якими працює плагін |
| Red Dead Online | Мережевий режим гри. Свідомо поза межами проєкту: при виявленні мережевої сесії плагін відновлює оригінальні значення й припиняє роботу |
| Пед (ped) | Персонаж-неігровий або ігровий у термінології RAGE. Гравець також є педом; детектор бою розрізняє гравця, ворожих педів і тварин |
| Dead Eye | Ігрова механіка сповільнення часу при прицілюванні. Може зараховуватися як ознака бою, але за замовчуванням цей сигнал вимкнено |
| Розшук законом (wanted) | Стан активного переслідування гравця правоохоронцями. Використовується як окремий сигнал бою, увімкнений за замовчуванням |
| Оверхол зброї (weapon overhaul) | Стороння модифікація, що переписує `weapons.ymt` цілком — баланс шкоди, віддачі, розкиду, перезарядки. Приклади, з якими проєкт зіставлявся: *Rededrunk's Ultimate Combat Overhaul*, *Catalogue Improvements* |
| NexusMods | Майданчик розповсюдження модифікацій; основний канал публікації релізу (автор RedziYT) |

## 2. Платформа плагінів

| Термін | Визначення |
|---|---|
| ASI | Динамічна бібліотека Windows (`.dll`), перейменована в `.asi` — загальноприйнятий формат плагінів для ігор Rockstar. Проєкт збирає `DynamicReloadSpeed.dll` і перейменовує її на `DynamicReloadSpeed.asi` пост-білд-кроком |
| ASI-лоадер | Компонент, що при старті гри сканує її кореневу теку та завантажує всі знайдені `.asi` у процес гри. У цьому проєкті — `dinput8.dll` зі складу ScriptHookRDR2 |
| ScriptHookRDR2 | Бібліотека, що дає стороннім плагінам доступ до нативних функцій гри, реєстрацію скрипт-потоку та обробника клавіатури. Єдина зовнішня залежність C++-компонента |
| SDK (ScriptHookRDR2 SDK) | Комплект заголовків (`inc/`) та бібліотеки імпорту (`ScriptHookRDR2.lib`) для збирання плагіна. У репозиторій не комітиться: тека `inc/` містить лише README з вказівкою, звідки взяти SDK |
| Натив (native) | Внутрішня функція скриптового рушія гри, викликана за хешем. Проєкт використовує нативи для детекції бою; кожен натив має бути підтверджений і зафіксований у `docs/NATIVES.md` |
| NativeDB | Публічний довідник нативів RDR2 (`alloc8or.re/rdr3/nativedb/`). Єдине джерело підтвердження імені, хеша та сигнатури натива; використовується на етапі розробки, не в рантаймі |
| Скрипт-потік | Потік виконання, наданий ScriptHookRDR2 плагіну. Уся робота з пам'яттю та нативами виконується тільки в ньому |
| Тік | Одна ітерація головного циклу скрипт-потоку. «Гарячий шлях» — тіло тіка, де заборонені виділення пам'яті, файловий ввід-вивід і форматування рядків |
| LML (Lenny's Mod Loader) | Стороннє завантажувальне середовище для модифікацій ігрових даних, зокрема `.ymt`. Опційний спосіб встановити оброблений `weapons.ymt`; плагін LML не вимагає й від нього не залежить |

## 3. Дані гри та формат

| Термін | Визначення |
|---|---|
| `.ymt` | Метафайл RAGE з ігровими даними. У випадку `weapons.ymt` — XML-подібний текст, який гра розбирає при завантаженні |
| `weapons.ymt` | Метафайл із параметрами всієї зброї. У типовому злитому вигляді містить близько 88 000 рядків. Читається грою **один раз**, під час завантаження |
| RPF-архів | Контейнерний формат архівів RAGE, усередині якого гра зберігає метафайли. Видобування `weapons.ymt` з архіву та його встановлення назад виконуються сторонніми інструментами і до меж проєкту не належать |
| `CWeaponInfo` | Структура даних одиниці зброї (ім'я, балістика, параметри перезарядки). Глобальна для всієї гри: спільна для гравця й усіх NPC |
| `CSectionedReloadInfo` | Структура профілю поштучної перезарядки (трубчастий магазин, барабан). На один профіль може посилатися кілька одиниць зброї |
| `WeaponReload` | Вузол усередині `CWeaponInfo`, що містить параметри перезарядки, зокрема `AnimReloadRate` |
| `AnimReloadRate` | Темп відтворення анімації перезарядки (`CWeaponInfo`). Менше значення — повільніша перезарядка |
| `TimeBetweenBulletsInLoop` | Пауза між вставлянням окремих набоїв при поштучному заряджанні (`CSectionedReloadInfo`), у секундах. Більше значення — довша перезарядка |
| `LoopRate` | Темп циклу вставляння одного набою (`CSectionedReloadInfo`). Менше значення — повільніший цикл |
| Ванільні значення (vanilla) | Значення параметрів, що постачаються з грою без модифікацій. Еталонна таблиця таких значень зберігається в секції `[Vanilla]` INI і використовується лише режимом `Mode=auto` |
| `VanillaEpsilon` | Допуск порівняння знімка з таблицею `[Vanilla]` (за замовчуванням `0.02`). Різниця в межах допуску вважається збігом |
| joaat | *Jenkins one-at-a-time* — алгоритм хешування рядків, яким RAGE ідентифікує імена (зброї, профілів, моделей). Рядок перед хешуванням переводиться в нижній регістр. У даних зустрічається у вигляді `0x`-рядка, наприклад `0xD06705B5` |
| Дублікат `CWeaponInfo` | Два або більше записи з однаковим `Name` у межах одного файлу — типовий наслідок злиття кількох оверхолів. Гра бере одне з входжень, тож при різних значеннях результат у грі непередбачуваний |

## 4. Робота з пам'яттю

| Термін | Визначення |
|---|---|
| Патерн-скан (сигнатурний пошук) | Пошук у завантаженому модулі гри заданої послідовності байтів із «дикими» позиціями. Проєкт цього способу **не** застосовує: за AD-02 ціль знаходиться за joaat-хешем імені стволу. Термін наведено, бо трапляється в описі відкинутої первинної редакції |
| Патерн | Байтова послідовність, за якою шукають структуру в образі модуля. У проєкті не використовується: у коді немає жодного патерна, а секція `[Memory]` таких ключів не містить і не може містити (AD-02) |
| Офсет | Зсув поля відносно початку структури. У конфігу не задається: вимірюється перебором вікна `[0, MaxOffsetWindow)` і приймається за консенсусом стволів. У `[Memory]` є лише необов'язковий примусовий офсет у тих самих межах — щоб після оновлення гри мод лагодився правкою текстового файлу |
| `VirtualQuery` | Системний виклик Windows для перевірки стану ділянки пам'яті. Використовується перед кожним записом: вказівник має належати закомміченій області |
| `VirtualProtect` | Системний виклик зміни прав доступу до сторінки пам'яті. Використовується за схемою «зняти захист → записати → відновити захист»; сторінка не лишається відкритою для запису |
| Знімок (snapshot) | Копія оригінальних значень трьох полів, знята один раз під час ініціалізації. Джерело для відновлення при вимкненні мода і еталон для перевірки «ніхто інший не писав у цю адресу» |
| Кламп (clamping) | Примусове обмеження значення діапазоном `[MinValue, MaxValue]` перед записом у пам'ять. Кожне спрацювання фіксується в лозі |
| Межа DLL | Межа між кодом плагіна та кодом гри. Жоден виняток не має права її перетнути |

## 5. Поведінка плагіна

| Термін | Визначення |
|---|---|
| Профіль перезарядки | Набір із трьох значень (`AnimReloadRate`, `TimeBetweenBulletsInLoop`, `LoopRate`) для конкретної зброї в конкретному стані. Кожна зброя має два профілі: `CALM` і `COMBAT` |
| `CALM` | Стан поза боєм. Діють повільні, реалістичні значення перезарядки. Стан за замовчуванням після успішної ініціалізації |
| `COMBAT` | Стан бою. Діють швидкі, близькі до ванільних значення. Вхід у стан — миттєвий, за будь-яким істинним сигналом |
| `COOLDOWN` | Проміжний стан після зникнення всіх ознак бою. Значення лишаються бойовими, працює таймер `CooldownSeconds`. Повернення сигналу скасовує таймер і повертає стан у `COMBAT` |
| Гістерезис | Асиметрія переходів: вхід у бій миттєвий, вихід — із затримкою. Запобігає перемиканню на повільну перезарядку між хвилями ворогів |
| Сигнал бою | Незалежна ознака бою (стрільба, ближній бій, недавня шкода, ворожий пед поблизу, розшук, прицілювання, Dead Eye). Кожен сигнал вмикається окремим ключем у секції `[Signals]` і має власний тег у лозі |
| Підтверджуваний сигнал | Сигнал, який сам по собі не є ознакою бою й зараховується лише в поєднанні з іншим. Такий сигнал — прицілювання: без ворога поблизу чи недавньої шкоди полювання не вважається боєм |
| `DetectorHz` / `PedScanHz` | Частоти опитування: загальна частота детектора (за замовчуванням 4 Гц) та частота дорожчого сканування педів поблизу (за замовчуванням 2 Гц) |
| `ThreatRadius` / `MaxPedsScanned` | Радіус пошуку ворожих педів (за замовчуванням 80,0 м) і верхня межа кількості кандидатів на один прохід (за замовчуванням 32) |
| `CooldownSeconds` | Тривалість стану `COOLDOWN` перед поверненням у `CALM` (за замовчуванням 5,0 с) |
| `DamageMemorySeconds` | Час, протягом якого отримана шкода продовжує вважатися ознакою бою (за замовчуванням 8,0 с) |
| Джерело значень профілю | `ini` — абсолютні числа з секції зброї; `snapshot` — значення, завантажені грою при старті; `multiplier` — знімок, помножений на коефіцієнт із `[Defaults]` |
| `Mode=auto` / `Mode=manual` | Режим призначення профілів: `auto` вирішує по кожній зброї, порівнюючи знімок із `[Vanilla]`; `manual` виконує `CalmSource` / `CombatSource` буквально і дає однакову поведінку на будь-якій машині |
| Пресет | Готовий INI-файл із набором значень (`realistic.ini`, `hardcore.ini`, `subtle.ini`), який користувач кладе замість ручного налаштування 24 стволів |
| Відкладений запис | Відмова записувати значення, доки гравець перезаряджається; запис переноситься на наступний тік із записом у лог. Запобігає десинхронізації або зависанню анімації |

## 6. Препроцесор та його артефакти

| Термін | Визначення |
|---|---|
| `ymt-tweaker` | Офлайн-препроцесор `weapons.ymt` на Python; чинна версія — 5.0.1 |
| `target_full_s` | Єдине число, яким задається калібрування стволу: бажана тривалість повної перезарядки в мирному профілі. Три значення полів виводяться з нього, а не підбираються вручну |
| Модель темпів (`coupled` / `independent`) | Дві гіпотези про те, чи масштабує `AnimReloadRate` поцикловий крок вставляння набоя. Експеримент у грі 2026-09-21 підтвердив `coupled`: масштабує, тому `LoopRate` при зміні темпу не чіпається |
| `ABSENT_IN_YMT` | Перелік стволів, для яких у `weapons.ymt` немає запису `CWeaponInfo` взагалі (LeMat, Navy, M1899, Evans, Elephant Rifle). Правкою файлу їх недосяжно; їх патчить тільки плагін за joaat-хешем імені |
| Лікування XML | Приведення вхідного тексту до стану, придатного для стандартного XML-парсера: зняття BOM, тимчасове перейменування тегів, що починаються з цифри чи дефіса (префікс `_HEALED_`), екранування «голих» `&` |
| Відновлення XML | Зворотна операція при серіалізації: зняття префіксів `_HEALED_`, щоб вихідний файл лишився придатним для гри |
| BOM | Маркер порядку байтів `U+FEFF` на початку файлу. Присутній у частині вхідних файлів і ламає розбір, якщо його не зняти |
| `RELOAD_CONFIGS` | Таблиця калібрування всередині препроцесора: цільові значення трьох полів і аліаси профілів для кожного ствола |
| `SectionedName` | Поле запису `RELOAD_CONFIGS` — ім'я або список імен профілів `CSectionedReloadInfo`, що належать цьому стволу |
| Підбір конфігу | Правило зіставлення імені зброї із записом таблиці: точний збіг → найдовший ключ-префікс → найдовший ключ-підрядок |
| `--report-only` | Режим, у якому препроцесор формує звіт і INI, але не записує оброблений `.ymt` |
| `weapons_reload_report.csv` | CSV-звіт по всіх стволах вхідного файлу: оригінальні та нові значення, статус обробки, посилання на профіль |
| `DynamicReloadSpeed.generated.ini` | Експортований конфіг плагіна: `Calm_*` — значення з таблиці калібрування, `Combat_*` — значення, знайдені у вхідному файлі |

## 7. Процес розробки

| Термін | Визначення |
|---|---|
| Specification-Driven Development (SDD) | Підхід, за якого специфікація є джерелом істини: зміна поведінки спершу фіксується в специфікації, і лише потім у коді |
| ШІ-агент | Виконавець коду за специфікацією (Antigravity IDE) під контролем розробника. Обмежений правилами політики проєкту: не змінює специфікацію самостійно, не використовує непідтверджених нативів |
| `docs/NATIVES.md` | Реєстр підтверджених нативів: ім'я, хеш, точна сигнатура, місце підтвердження |
| `docs/UNVERIFIED.md` | Перелік потрібних, але не підтверджених механізмів. Порожній файл — валідний результат |
| Префікс коміта | Обов'язкова позначка типу зміни на початку повідомлення коміта: `[INIT]`, `[DOCS]`, `[FEAT]`, `[FIX]`, `[POLICY]`, `[RELEASE]` |
