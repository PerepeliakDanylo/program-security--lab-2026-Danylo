# drs_release — офлайн-інструмент супроводжувача релізів

Цільова тека в репозиторії: `tools/drs_release/`

Цей інструмент **не є частиною гри й не є частиною ASI-плагіна**. Його запускає
супроводжувач у власному терміналі, щоб керувати релізами мода DynamicReloadSpeed:
автентифікуватися, (далі в ЛР5-ЛР8) керувати доступом, підписувати збірку, ротувати
ключі й перевіряти цілісність. Пароль вводиться через `getpass` — так само, як це роблять
`sudo` чи `git` — тому **жодного перехоплення введення в процесі гри немає**.

## Файли

| Файл | Призначення | Лаба |
|---|---|---|
| `accounts.py` | ядро автентифікації: PBKDF2-верифікатор, блокування, журнал | ЛР4 |
| `drs_release.py` | CLI: `init`, `add-user`, `login` + інтерактивна сесія | ЛР4 |
| `README.md` | цей файл | ЛР4 |

Наступні лаби додають: ролі RBAC + умови ABAC (ЛР5), TOTP і конвертне шифрування
секрету (ЛР6), HMAC-цілісність файлу та маніфест релізу (ЛР7), підписаний паспорт
релізу (ЛР8).

## Залежності

Ядро автентифікації (ЛР4) використовує **лише стандартну бібліотеку Python**
(`hashlib`, `hmac`, `json`, `re`, `secrets`). Пакет `cryptography` знадобиться пізніше
(AES-256-GCM, HKDF, Ed25519 у ЛР6-ЛР7) і тоді буде доданий у `requirements.txt`
окремим комітом `[POLICY]` з дозволу власника.

## Використання

```
python drs_release.py init
python drs_release.py add-user maintainer --role maintainer
python drs_release.py login maintainer
```

У сесії: `help`, `whoami`, `status`, `exit`.

Ім'я користувача — латиниця, цифри, `_`, `.`, `-`, до 32 символів. Пароль — щонайменше
12 символів.

## Модель захисту (стисло)

* Пароль → PBKDF2-HMAC-SHA256, 600 000 ітерацій, сіль 16 Б → майстер-секрет (не зберігається).
* У файлі лежить лише верифікатор = HMAC-SHA256(master, "drs-release/verifier").
* Перевірка пароля — стала за часом (`hmac.compare_digest`).
* 5 невдалих спроб → блокування 5 хв, далі подвоєння до межі 60 хв.
* PBKDF2 рахується за **будь-якої** відмови — і для невідомого, і для заблокованого
  запису, — тож час відповіді не видає ні існування акаунта, ні стану блокування.
* Будь-яка невдача входу → одне загальне повідомлення; подробиці лише в журналі аудиту.
* Запис файлу атомарний (`tmp` + `os.replace`); керувальні символи в журнал не потрапляють.

## Відомі обмеження (ЛР4)

* Ролі ще не застосовуються: `add-user` у CLI доступний без входу. ЛР5 залишає його лише
  для бутстрапу першого власника, далі — лише в сесії `owner`.
* Тайм-аути сесії (простій 10 хв / абсолютний 60 хв) перевіряються на кожній команді.
  Заблокований виклик `input()` примусово не закривається — для інструмента в терміналі
  супроводжувача це прийнятно; закриття відбудеться за наступного Enter.
* Цілісність самого файлу облікових записів захищається HMAC у ЛР7.
